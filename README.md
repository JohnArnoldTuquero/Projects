# 📋 Project Development Process

Every project should follow this general process:

```text
1. Choose an idea
       ↓
2. Define the problem
       ↓
3. List the features
       ↓
4. Choose the technology
       ↓
5. Plan the project
       ↓
6. Build the minimum version
       ↓
7. Test and debug
       ↓
8. Improve the project
       ↓
9. Document everything
       ↓
10. Push to GitHub
```

---

# 🧠 Before Starting a Project

Ask myself:

### 1. What am I building?

Clearly define the project.

### 2. What problem does it solve?

Even a small project should have a purpose.

### 3. What will I learn?

Identify the programming concepts or technologies I want to practice.

### 4. What are the core features?

Start small.

Don't build 30 features immediately.

### 5. What technologies will I use?

Choose technologies appropriate for my current skill level.

### 6. What should I know before starting?

Identify concepts I need to learn first.

---

# 🛠️ Build Rules

## Rule 1 — Don't blindly copy tutorials

Tutorials are allowed for learning.

But I should eventually be able to:

* Explain the code
* Modify the code
* Debug the code
* Add my own features
* Rebuild important parts without copying

> **If I can't explain it, I don't truly understand it yet.**

---

## Rule 2 — Start simple

Build the minimum working version first.

```text
MVP
 ↓
Working Project
 ↓
Improvements
 ↓
Advanced Features
```

Don't spend weeks planning something that I haven't even started.

---

## Rule 3 — Every project should teach something

A project doesn't need to be revolutionary.

It needs to help me learn.

Examples:

```text

→ DOM + Events + LocalStorage

Weather App
→ APIs + Async JavaScript

Banking System
→ OOP

→ OOP + SQL

→ Python + AI APIs
```

# 📁 Standard Project Structure

The structure depends on the technology, but projects should generally contain:

```text
project-name/
│
├── README.md
├── src/
├── assets/
├── screenshots/
└── .gitignore
```

Not every project needs every folder.

For simple web projects:

```text
project-name/
│
├── README.md
├── index.html
├── style.css
├── script.js
├── assets/
└── screenshots/
```

For larger applications, use the structure recommended by the framework or technology.
